# Web TTS 구현 계획

관련 이슈: #132 (기존 #129). 기준: `origin/dev df13a06`, 2026-10-14 fetch.
요구사항: 작업 폴더 `Doc/tts-impl-spec/07-web-작업-정리.md`, 공통 계약 00, Web 명세 04, 카탈로그 명세 06.

## 확정 범위와 순서

1. W-A: 공통 VoiceIndex·성별 카탈로그를 정의하고 SOLO/MULTI 저장 요청에 번호를 연결한다. 잘못된 MULTI 성별과 미사용 성별 함수를 정리한다. 단독 PR로 배포할 수 있다.
2. W-B: 기존 chatInstance로 인증을 유지하는 오디오 long-poll API·파서를 추가한다. 20초 대기, 30초 클라이언트 타임아웃, 취소/404/형식 오류를 구분한다.
3. W-C: 질문·세션별 요청/Audio 수명, 메모리 자동 재생 이력, 정지 후 억제, 사용자 재생 및 재생 차단 상태를 구현한다. 오류는 1·2·4초 뒤 재시도하고 전체 대기는 180초로 제한한다.
4. W-D~F: 세션 훅·종료·녹음·제출에 연결하고 응답 시간을 녹음 시작/텍스트 첫 입력부터 계산한다. 직접 합성 훅·프리셋·스타일 전달을 삭제하고 질문/면접관 강조·녹화·업로드 흐름을 유지한다.
5. W-G: 저장 요청 검증과 실제 브라우저 오디오·녹화 회귀를 실행한다. lint/build 및 자체 리뷰 뒤 커밋·push·PR한다.

## 기술 가정

- 브랜치: `codex/132-tts-voice-index`, 후속 `codex/132-tts-audio`. 후속 PR은 첫 브랜치를 기준으로 만들어 리뷰 범위를 분리한다.
- 07의 호환성 보완대로 QUEUED/GENERATING은 PENDING으로 접는다. 04의 정상 응답 검증에 대한 명시적 확장이다. PENDING 수신은 연속 오류 횟수를 초기화한다.
- READY URL은 HTTPS만 허용한다. 브라우저 회귀도 HTTPS 가상 저장소 URL을 라우팅하여 무음 WAV를 제공한다(07의 data URL 예시는 HTTPS 파서와 충돌하므로 사용하지 않는다).
- 응답 questionId가 요청과 다르면 형식 오류로 재시도한다. 다른 질문의 음성이 섞이지 않게 한다.
- 전체 대기 상한은 통신 오류·대기 중 요청에도 적용하며 정지 시 진행 중 play Promise도 무효화한다. 질문 번호 0은 null과 구분한다.
- 텍스트 첫 입력 시각은 공백이 아닌 첫 글자 입력 때 기록한다(07의 trim 기준). 삭제 후 다시 입력해도 최초 시각을 유지한다.
- 패키지를 추가하지 않는다. 기존 외부 Playwright 런타임과 Chromium을 사용한다.
- 원격 코드 재확인: SOLO의 interview-content에는 음성 버튼이 없다. W-E는 MULTI 버튼 상태 변경과 함께 SOLO에 같은 문구·상태의 버튼/실패 안내를 추가하여 두 모드 수동 재생 요구를 충족한다. 공통 오디오 컨트롤로 표시를 일치시킨다.

## 검증 기준

- SOLO 1~4 / MULTI 5명 저장 본문 voiceIndex·gender, 슬롯 순서 변경, 저장 오류 시 진행 차단
- 음성 자동 1회 / 텍스트 수동, 재재생 시 재조회 없음, 답변 시작 전후 정지 및 늦은 READY 억제

## 배포와 후속 작업

W-A 이후 W-B~G 순서. 오디오 전환 PR은 Chat 운영 설정·실제 READY/S3 URL 확인 전 draft로 둔다.
실환경 W1~4·W9의 성별·말투·선합성은 운영 통합 검증이 필요하다.
W-H의 키·프록시·환경변수 정리는 운영 안정화 이후 별도 배포한다(D10). 후속 이슈 #134에서 시작 조건과 작업을 추적한다. 운영 값을 문서에 복사하지 않는다.
Chat 비종료 응답 정규화·운영 CORS·최종 음성 튜닝은 Web 밖의 후속 작업이며 이번 코드 변경 범위에 포함하지 않는다.
