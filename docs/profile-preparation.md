# 자료 분석 상태와 면접 준비 검증

마이페이지 저장은 최초 상태 조회 중, 확인된 `PENDING`, 재분석 요청 중에 차단한다.
최초 조회가 실패하면 오류 안내와 재조회 버튼을 표시하면서 자료 저장을 허용한다.
저장 성공 시 응답의 `jobId`로 분석 중 표시와 폴링을 시작한다.
이미 `PENDING`으로 확인된 분석은 이후 조회가 실패해도 저장 차단을 유지한다.
면접 설정은 조회 오류 중에 시작을 허용하지 않는다.

면접 준비 완료는 `preparationStatus === "READY"`로 판단한다.
`WAITING` 기본 폴링 간격은 3초, 그 밖은 1초이며 서버의 `retryAfterMs`가 더 길면 그 간격을 따른다.
현재 서버는 `retryAfterMs`에 null을 반환하므로 기본 간격을 사용한다.
최신 원질문 개편 계약은 종합 데이터 분석과 질문 대기를 모두 포함하도록 클라이언트 상한을 약 20분으로 정정했다.
따라서 이전 명세의 180초로 줄이지 않고, 서버의 `FAILED` 판정과 클라이언트의 20분 안전 상한을 유지한다.

## 실행

`npm run lint`, `npm run build`와 개발 서버를 실행한 뒤 아래 회귀 검증을 실행한다.
프로젝트에 테스트 패키지를 추가하지 않았으며, 외부 Playwright 런타임은 `PLAYWRIGHT_MODULE_PATH`로 지정할 수 있다.

```sh
node tests/profile-preparation.browser.mjs
node tests/interview-recording.browser.mjs
```

개발 서버 주소는 `INTERVIEW_TEST_ORIGIN`으로 지정한다(기본 `http://127.0.0.1:5173`).
자료 분석 검증은 다음 경로를 브라우저에서 확인한다.

- 최초 조회 중 저장 차단, 조회 실패 후 인증된 자료 업로드, 분석 중에서 완료로 복구.
- 완료 자료 변경의 확인·취소와 확인 후 저장, 분석 중 폴링 오류에도 저장 차단 유지.
- 실패 사유 4종의 복구 버튼과 재분석 요청.
- 1:1·다면의 완료·자료 유무·분석 중·실패·조회 오류별 시작 허용 여부와 재조회 복구.
- 1:1·다면의 면접 시작 404 안내와 마이페이지 링크.
- 질문 대기 안내, 서버 지정 폴링 간격, 준비 완료, 재시도 요청 실패 후 다시 재시도.
- 재시도 불가능한 실패, 안전 타임아웃, 화면 이탈 후 폴링 중지.

테스트는 API·소켓을 모의한다. 자료 분석 5초 폴링은 테스트 안에서 100ms로,
20분 안전 타임아웃은 해당 시나리오에서만 200ms로 줄인다. 면접 준비 폴링 간격은 실제 시간으로 검증한다.
실제 서버 분석 완료와 업로드 저장, 실장치 녹화 호환성은 별도 검증이 필요하다.
